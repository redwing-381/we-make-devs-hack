# Why-Graph

**Your AI engineers ship 24/7. Why-Graph is the shared graph brain that works out why prod broke, proves it
with a path, and makes sure no agent ships that mistake twice.**

Built for [Graph Hacks: Context for AI Agents](https://www.wemakedevs.org/hackathons/falkordb) (WeMakeDevs ×
FalkorDB, Oct 15–18 2026).

**Tracks entered:**
1. Agents That Act on Connected Data
2. Agent Memory and Coordination
3. Company Brain

> Status: base scaffold. Features land as PRs; see [docs/features.md](docs/features.md).

## What it does

1. **Investigates.** When an alert fires, four agents share one FalkorDB graph as a blackboard:
   - **Triage** finds the root alert and the blast radius.
   - **Cause** ranks the recent changes upstream of it.
   - **Memory** matches the incident's *shape* against past incidents.
   - **Comms** drafts the status update and pages the owners.
2. **Proves.** Every claim is a path in the graph, with the Cypher that produced it. Click a claim to re-run that
   query live.
3. **Remembers.** A resolved incident becomes a Lesson plus an executable **Detector**, which is stored Cypher.
4. **Prevents.** Our AI SDE agents call Why-Graph over **MCP** (`check_change_risk`) before opening a PR, so a
   lesson learned once stops the same mistake on a different service.

**Graph-only mode** turns the LLM off. The root cause, evidence paths and lesson matches stay the same, because
they come from graph queries. The LLM only writes the narrative.

## Architecture

```
 SDE agents ──PR──▶ GitHub (astro-mini) ◀── GitHub ingester / PR Guard ─┐
     │ MCP                         │ merge                               ▼
     ▼                             ▼                                 FalkorDB  (one graph per tenant)
 Why-Graph API (FastAPI) ◀── deployer / watcher (deploys, telemetry, alerts)  ▲
   ├─ /mcp            check_change_risk · who_knows · why_is                   │
   ├─ orchestrator →  Triage ∥ Memory → Cause → Memory → Comms ── read/write ──┘
   ├─ SSE stream      every event also recorded as JSONL (replay)
   └─ /api/query/run  read-only, allow-listed catalog queries
 UI (React + Vite): Incident · PR Guard · Memory · Brain · Replay
```

## Quick start (local)

Prerequisites: Docker, [uv](https://docs.astral.sh/uv/), Node 20+.

```bash
cp .env.example .env        # fill in keys
make install                # uv sync + npm install
make db                     # FalkorDB on :6379, Browser on http://localhost:3000
make smoke                  # verify every FalkorDB feature we rely on
make api                    # API on http://localhost:8000  (docs at /docs)
make ui                     # UI on http://localhost:5173
make test                   # DB tests skip automatically if FalkorDB is down
```

The UI's Incident page replays `scenarios/recordings/act1-fixture.jsonl` over SSE, so UI work doesn't need the
agents or the database.
